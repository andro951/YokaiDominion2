# Yokai Dominion

A Japanese-fantasy MOBA being built in **C#** for Isaac Richards. Active repository: `andro951/YokaiDominion2`.

**Current milestone: a local three-lane vertical slice, not a finished game.** The client uses **Godot 4.7.2 .NET**. Combat, movement, equipment, and match state live in a separate **.NET 10** library with no engine dependency.

## Play a packaged build
The **Standalone desktop builds** Actions workflow produces Windows x64 and Linux x64 packages when its tests and exports succeed. Download the corresponding artifact from a successful run, extract the whole folder, and launch the executable. Read `docs/PLAYING.md`. Do not assume a queued or failed workflow produced a verified package.

## Run from source
1. Install the .NET 10 SDK and **Godot 4.7.2 .NET** (not the standard/GDScript-only editor).
2. Clone this repository. Run `dotnet build src/Yokai.Client/Yokai.Client.csproj -c Debug` from its root.
3. Import `src/Yokai.Client/project.godot` into Godot .NET and press F5.
4. Press Enter at the title screen. Right-click to move or attack; Q/W/E/R use abilities. F1 opens the full controls.

No paid assets are required. All currently included visual and sound assets are generated by this project's source. They are original development art, not final character assets.

## Validate
- `dotnet run --project tests/Yokai.Core.Tests -c Release`
- `dotnet run --project tests/Yokai.Match.Tests -c Release`
- `dotnet build src/Yokai.Client/Yokai.Client.csproj -c Debug`

CI runs the simulation suites and compiles the client on Windows and Linux. A graphical Linux test renders through Mesa/Xvfb and saves screenshots. Desktop packaging also launches the exported binaries, separately from the editor.

## Implemented in this milestone
- Three lanes, waves, towers, shrine victory, bot champion, deaths and respawns.
- Continuous movement, hex A*, swept terrain collision, 60 ms derived hex occupancy with independently timed 120 Hz combat.
- Vaelira's weapon-dependent Q timing, W attack reset, E trip, R leap, directional Blood Scent.
- Eleven equipment slots; strength requirements, per-weapon scaling, mixed armor sets, shrine purchasing/storage, levels and points.
- Original procedural shrine battlefield, proxy actors, camera controls, HUD, minimap, effects, synthesized audio, pause, saved mute/quality settings.

## Quality boundary
A compiling prototype is not a max-quality finished game. This repository preserves the long-term target while building and verifying useful milestones. Final character models/animation, volumetric tissue, sophisticated bots, the full item catalog, multiplayer authority, vision/fog, replays, real projectile collision, balancing, accessibility and hardware performance validation remain production work.
